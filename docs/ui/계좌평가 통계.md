# 계좌평가 통계

## 한 줄 정의

영업일마다 **계좌평가 스냅샷**을 한 번씩 쌓아, **계좌별 총수익률(`tot_prft_rt`) 추이**를 비교하고, 각 일자에 **스냅샷 시점에 부착돼 있던 전략(`strategy_id`)**을 붙여 전략 실험을 평가한다.

## 배경

모의투자 계좌 4개를 만들어 자동 매수·매도를 진행하고 있다.

## 목적

각 전략의 수익률 변화를 한눈에 모니터링하고, 전략을 수정·교체하며 최적에 가까운 전략을 찾는 것이 목적이다.

## 스케줄 (서로 다른 두 축)

### 자동 매수·매도(진입·청산 루프)

증권 **영업일**에 **매 시간 10분**(예: 09:10, 10:10, …)에 종목을 찾으며, 이미 보유 중인 종목은 제외한다.  
(이 주기는 **통계 스냅샷**과 무관하다.)

### 계좌평가 스냅샷(일 1회)

**하루에 한 번**, Kiwoom 계좌평가잔고 응답과 당시 활성 전략 메타를 MongoDB `account_evaluation_snapshots`에 저장한다.  
통계 차트의 가로축은 **일자별 한 점**이 된다.

**trading-agent 기본 크론(환경 변수 미설정 시)**  
`ENTRY_SCHEDULER_TIMEZONE`(기본 `Asia/Seoul`) 기준, 요일 `STATISTICS_EVALUATION_SNAPSHOT_DAY_OF_WEEK`(기본 `mon-fri`), 시각 `STATISTICS_EVALUATION_SNAPSHOT_HOURS`:`STATISTICS_EVALUATION_SNAPSHOT_MINUTES`(기본 **16:10**).  
배포 환경에서 값을 바꿨다면 이 문서의 “기본 16:10”과 다를 수 있으니 실제 설정과 맞춘다.

## 통계 화면이 보여 주는 것

- **지표**: 스냅샷 문서의 **`tot_prft_rt`(총수익률, %)** 만으로 날짜별 라인을 그린다.
- **필터**: API·DB와 동일한 키인 `qry_tp`(조회구분), `dmst_stex_tp`(거래소). 성공 응답(`return_code=0`)만 연결한다.
- **전략 연계**: 문서에 저장된 `strategy_id`를 범례·전략 변경 마커 등으로 노출해, **어느 구간이 어느 전략인지** 해석할 수 있게 한다.

## 계좌평가 잔고내역과의 역할 분담

| 구분 | 역할 |
|------|------|
| **계좌평가 통계** | 기간·계좌 간 **추이 비교**, 전략 교체 시점과 수익률 곡선의 대응 |
| **계좌평가 잔고내역** | **당시점** 종목별 평가손익·수익률 등 **상세 잔고** 확인 |

## 전략 (도메인)

각 계좌는 1개의 활성화 전략을 가질 수 있다.

1. **종목 진입 조건 (`entry_filter`)** — 어떤 종목을 매수할지 필터 조건  
2. **종목 손절·익절 조건 (`rules`)** — 정해진 룰에 따라 전량 매도

## 계좌·실험 사이클

모의 투자에서는 활성화된 계좌를 최대 4개까지 운영할 수 있다. 대략 2주 전후(또는 며칠) 자동 매매를 진행하며, 자세한 수익률·종목 내역은 **계좌평가 잔고내역**에서 본다.  
수익률이 나쁜 전략은 폐기하고, 새 계좌에 새 전략을 붙여 다시 돌린다. 이를 반복해 전략을 다듬는다.

## 비목표

- 세무·회계 단위의 확정 손익, 법적 보고용 수치
- 실계좌 운용(이 문서·통계 화면 설명은 **모의** 맥락이 기본)
- 지수 벤치마크(코스피 등) 자동 비교 — 별도 데이터 소스·기능이 필요하면 후속 과제

## 데이터 보관

스냅샷 TTL·아카이브 정책은 운영 정책에 따른다. 단기 실험(약 2주)만 보더라도 장기 보관 시 디스크·조회 비용을 고려한다.
